Ты — Senior Java/Vert.x инженер. Мне нужно разработать асинхронное чат-приложение (кейс по типу ICQ) согласно строгим техническим требованиям.

ТЕХНИЧЕСКИЙ СТЕК:
- Java 21
- Сборщик: Gradle (Kotlin DSL: build.gradle.kts)
- Сервер: Eclipse Vert.x (HttpServer, WebSocket, Router) — БЕЗ SPRING
- База данных: PostgreSQL (использовать vertx-pg-client, реактивное неблокирующее общение)
- JSON: Jackson / Vert.x JsonObject
- Клиент: Минималистичный, стильный Web-интерфейс (HTML5, Tailwind via CDN, чистый JS с WebSockets) в src/main/resources/webroot/index.html.
- Контейнеризация: Dockerfile (multi-stage build), docker-compose.yml.

ФУНКЦИОНАЛЬНЫЕ ТРЕБОВАНИЯ:
1. Аутентификация/Вход: пользователь вводит логин при входе. Если пользователя нет — он создается в БД.
2. Список диалогов / пользователей: отображение доступных пользователей и статуса их онлайна.
3. 1-to-1 сообщения в реальном времени через WebSocket.
4. Статусы сообщений: SENT (отправлено), DELIVERED (доставлено адресату), READ (прочитано).
5. Сохранение истории сообщений в PostgreSQL. При открытии диалога история подгружается из БД.
6. Веб-интерфейс должен позволять открыть две вкладки браузера под разными пользователями и вести полноценный диалог со сменой статусов сообщений (галочки: отправлено / доставлено / прочитано).

ТРЕБОВАНИЯ К АРХИТЕКТУРЕ КОДА:
- Четкое разделение:
    * ChatVerticle (инициализация HTTP/WebSocket роутов, static handler для UI).
    * ConnectionManager (управление активными WebSocket-сессиями пользователей).
    * ChatRepository (реактивные SQL-запросы к PostgreSQL: сохранение, загрузка истории, апдейт статусов).
    * Models/DTO (Java Records для сообщений, статусов, WS-событий).
- Скрипт инициализации БД (schema.sql) с таблицами `users` и `messages`.

3. Весь исходный Java-код (с корректными пакетами, обработкой ошибок и неблокирующим I/O).
